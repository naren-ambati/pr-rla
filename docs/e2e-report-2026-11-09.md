## B. The full lifecycle on recorded data

`_e2e-live/recorded/` is a copy of `test/fixtures/audits/gh-aw-q3-recorded` (the Copilot stratum of Q3 2026, N = 1,589, drand round 33,245,812, synthetic clock and key).

| Command | Result |
|---|---|
| `status` | `prefix 0/36 … NOT CERTIFIED · 36 more passing draws needed`, exit 0 |
| `verify --offline` | check 4 BLS PASS (the round is carried in `draws.json` and BLS-verified), 6 PASS (36/36 draws reproduce), 1 to 3 INCOMPLETE (no timestamp authority is configured, so the times are the signer's own clock), 5 SKIP; **INCOMPLETE, exit 6** |
| `verify --beacon-file …` (online, replay) | the same, with check 5 PASS: population 1,589/1,589 rebuilt from the recorded export |
| `draw-context 1`, `draw-context 2` | 8.4 KB and 5.3 KB; the change, CI, checklist, fenced untrusted text |

**Signed verdicts need a registration that names the key.** `record --sign` on the recorded fixture is refused: `--sign needs the built-in git-file ledger and a registration with verdicts.allowed_signers`, and the fixture's registration (signed, on a fake clock) names none. So for the verdicts I built `_e2e-live/recorded-signed/`: the same recorded population, protocol and drand round, re-registered by the fixture's own builder (`scripts/build-gh-aw-recorded-audit.mjs`, copied to `_e2e-live/build-signed.mjs`) with `verdicts.allowed_signers` holding a throwaway ed25519 key made in a temp directory. Its draws differ (they are bound to the registration), and the recorded draw descriptions belong to the original, so `draw-context` was run on the original.

**36 DEMO verdicts** (`record N pass --reviewer demo-reviewer --note "DEMO verdict, not a review" --sign <key>`), committed. Two draws named a change already drawn (draws 6 and 36), and `record` refused to append: `github:github/gh-aw#56274 already has a pass verdict (draw #3); a change drawn twice reuses its first verdict`. So 36 draws are counted from 34 distinct verdicts, and the prefix is 36/36.

- Before committing, `status` printed `ledger integrity FAILs: 1 verdict line(s) not yet committed` and, once the target was reached, `CERTIFICATE WITHHELD (… verify check 7 would FAIL: the ledger's integrity check FAILs …)`; `verify` FAILED check 7 with `audit/2026-q3/verdicts.jsonl has never been committed, but the registration beside it is`. After the commit both clear.
- **The SPRT reached its target:** `prefix 36/36 · fails 0 · … LLR 3.066 / target 2.996 · target reached`.
- **`status` versus `verify`.** `status`: `CERTIFICATE WITHHELD (registration time unproven (TIMESTAMP NOT TAMPER-PROOF); manifest commitment time unproven …; population not verified: run pr-rla verify)`, exit 6. `verify`: checks 4, 5, 6 PASS, check 7 WARN, checks 1 to 3 INCOMPLETE; `INCOMPLETE: check 1 (registration), check 2 (manifest before seed), check 3 (seed round) could not be established; nothing failed, but this is not a verification (exit 6)`. Both withhold, but only `verify` rebuilds the population. VERIFIED needs times proven by k authorities, which a fixture on a fake clock cannot have; the CI job summaries (scenario F) show VERIFIED on a fixture with mock authorities.

## Bugs

**Fixed: `npm test` failed on master itself.** The first full run in a fresh worktree off master (880b62f) failed `test/single-repo-anchor.test.ts` (the other two failures were this round's own new docs, fixed in the same run). That test compares today's build with "master as the branch left it", found as `git merge-base HEAD master`. Wave 2 was merged into master (a fast-forward to 880b62f), so that merge-base is HEAD itself: the "master build" is this build, nothing differs from itself, and the assertion that master's verify threw the provider's 404 sees `undefined`. The earlier fresh-clone verification passed only because it cloned `fix/final` while master still sat at the end of wave 1. The anchor is now the fixed commit `e6e6ada` (the tip of `integrate/wave1`, master as wave 2 found it, an ancestor of every branch), and a new test pins that the anchor is an ancestor of HEAD and not its tip. No source (`src/`) changed; the Action's tarball was re-pinned anyway, because the README it packs gained the hero image.

What else the round found, none needing a source change:

1. **`status` exits 0 on a tampered ledger below the target.** After the deleted-FAIL attack `status` prints `ledger integrity FAILs: … was rewritten (not appended)` but exits 0, because the check-7 FAILs enter `status`'s exit code only once the target is reached (`withheld = report.sequence.state === "CERTIFIED" ? gate.withheld : []`, `src/api/read/status.ts`). `verify` and `status` at the target exit 1. A CI job that runs only `status` stays green on a tampered ledger until the target is reached. Not changed: the same path makes `status` exit 1 for an uncommitted verdict between `record` and `git commit`, which is a workflow call for the founder, not a fix.
2. **The MCP demo scripts print TAP noise** (`TAP version 13` … `# tests 0`) because `test/helpers.mjs` registers an `after` hook with `node:test` on import. The new demo's screenshot filters it with `grep -v`. Cosmetic.
3. **`pr-rla freeze --dry-run --estimate` ignores the window's age.** The same ~24,300 requests for any window that closed weeks ago, against ~70 for a recent one, because the listing walks back from today; this is true to how the provider lists, but the estimate does not say so.

Things that look like bugs and are not: `register --force` replaces a registration on a frozen audit (check 2 and 3 FAIL it, row 3 above); a registration made through the fixture builder (no git repository at that time) lacks the ledger path and warns about it; running `packages/pr-rla-mcp/scripts/clean-dist.mjs` from the repository root empties the root `dist/` (its own header says it removes `./dist`).

## What could not be run, and why

- **Sampling and the final verify on the live audit.** R publishes 24 hours after registration (2026-11-10T18:13:36Z). `FINISH.md` has the commands.
- **A live VERIFIED.** It needs a sampled audit whose times are proven. The CERTIFIED summary on a fixture with mock authorities is the closest an offline round gets.
- **Codex and Cursor.** `codex` is not installed; the `cursor` on PATH is the editor's command line, not the Cursor agent, so no hook run was attempted in either ([`manual-acceptance.md`](assistants/manual-acceptance.md) stays the founder's check).
- **Live writes.** No Rekor submission, no issue ledger, no checkpoint push, no `npm publish`, no remote, by the rules of the round. The GitHub issues ledger and the checkpoint timestamp renewal were exercised only on mock servers.
- **A second Claude Code run.** One run only, as the brief limited it; a guard that fails to start (`onFailure`) is untestable on 2.1.267.
